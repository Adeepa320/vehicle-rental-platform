# Processor register

**Status:** v0.1 draft (2026-10-17), Phase 10. Owner: founder (controller representative) until a data protection officer or privacy lead is named ([PLACEHOLDER: DPO_CONTACT]).
**Purpose:** the list of third parties that process personal data for the platform, kept for the Personal Data Protection Act (Part III, controller and processor duties; in operation from 1 January 2027 per Gazette 2498/16 of 22 July 2026, verified 2026-10-17) and referenced by the Privacy Notice (section "Service providers who process data for us") and the [cross-border transfer register](CROSS_BORDER_TRANSFER_REGISTER.md).
**Scope:** only vendors that are selected or shortlisted in docs/ARCHITECTURE.md §13 and docs/TECH_DECISIONS.md D10 / D42. Nothing has been purchased or signed. Every contract column reads **NOT YET EXECUTED**; every account is an **EXTERNAL GATE — NOT EXECUTED**.
**Facts:** vendor facts below come from the Phase 10 external verification (official vendor documentation read on 2026-10-17). Where a fact could not be confirmed it is marked "not confirmed".

## Not in this register

- **Mailpit** and **MinIO**: local development only (docker-compose), never in production.
- **GitHub**: source code and CI; no production personal data (test fixtures only). Secrets for CI are not planned to include production credentials.
- **Notify.lk / SMS**, **WhatsApp Business API**, **PostHog / Plausible analytics**, **MapTiler**: mentioned in planning documents but not selected; none may be added without a decision record (CLAUDE.md §6).

## Before launch (per processor)

1. Create the account under the operating company's name (EXTERNAL GATE — NOT EXECUTED for every row).
2. Download or execute the vendor DPA; record the date and the version in the "DPA / contract status" column.
3. Read the subprocessor list; note any that are outside Singapore / USA / EU.
4. Record the cross-border instrument relied on in the [cross-border transfer register](CROSS_BORDER_TRANSFER_REGISTER.md) (LEGAL REVIEW REQUIRED).
5. Set retention controls (Resend data retention, Sentry data scrubbing, R2 lifecycle and bucket locks, database backup retention) and note them in [DATA_RETENTION.md](../security/DATA_RETENTION.md).
6. Add the vendor's status page and support contact to [runbooks/INCIDENT_RESPONSE.md](../runbooks/INCIDENT_RESPONSE.md) (vendor escalation table).
